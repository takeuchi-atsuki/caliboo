# ホーム画面 (1b)

## 概要

ログイン後の起点となる画面。パステル配色とマスコット（デザインカンプID: 1b）を継承し、強みの確認を最優先にする。

- パス: `/home`
- 実装: `frontend/src/features/home/HomePage.tsx`
- データ取得: `GET /api/home/summary`（`useHomeSummary`フック）

## 構成要素

1. `TopNav`（共通レイアウト）: ロゴ、各画面へのナビ、認証レスポンスの本人の連続学習日数、テーマ切替、表示名・ロール・アバター、ログアウト。スマートフォンでは下部ナビも表示する（[UI改善仕様](../ui-refresh.md)参照）。
2. 見出し「ホーム」と案内「今日も、自分のペースで。一歩ずつ進めていこう。」。
3. 今のあなたの強み: 最上段の全幅パネル。ラベンダー系の背景・大きい見出し・塗りのボタン「強みを詳しく見る」（`/strengths`）で優先度を示す。承認済み候補の可変件数のタグと、根拠・成長のヒントを確認できる案内を表示する。強みがない場合は日報や課題が材料になることを案内する。`Mascot`（112px、mood="happy"）は600px以上で右側に置き、それ未満では隠して本文の幅を確保する。
4. 今日のふり返り: APIの挨拶と「3分でOK」の案内、アウトラインの「日報を書く」（`/report`）を表示する。本文内の日報への導線はこの1か所に集約する（共通ナビは別）。
5. 「今日は何をしよう？」: 「課題に取り組む」（`/assignments`）・「資格勉強」（`/study`）・「OJT」（`/ojt`）の3枚。アイコン・ラベル・説明・遷移先はAPIのレスポンスを使う。
6. 資格の学習度: 最下段のコンパクトなパネル。見出し「{資格名}の学習度」、`DonutProgress`（88px）の達成率と「学習を続ける」（`/study`）を表示する。`progressbar`の名前・現在値・範囲（0〜100）を支援技術にも伝える。進捗と無関係な「あと少し」という断定はしない。

取得待ちは骨格表示と`role="status"`、失敗時はエラーAlertを表示する。本文には`main`と見出し階層を設ける。

!NOTE: ショートカットカードの遷移先はバックエンドのレスポンス(`shortcuts[].to`)側で持たせている。フロントに固定文字列でハードコードすると、将来ルーティングを変更した際にAPI側と画面側で二重管理になるため、レスポンスの`to`フィールドをそのまま`Link`の`to`propに使う設計にした。

!NOTE: 強み→ふり返り→行動の選択→学習度の順序を、全画面幅の表示順・DOM順・キーボード操作順で揃える。日報のショートカットを課題へ置き換えたのは、ふり返りの専用導線との重複を解消し、課題にもホームから直接到達できるようにするため。

設計の参照: W3Cの[意味のある順序](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence)、[リンクの目的](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html)。

- 4つのセクションは全幅の縦並び。ショートカット3枚、およびふり返り・学習度の本文とボタンは`md`(900px)未満で縦積みに切り替わる。600px未満では専用ボタンを横幅いっぱいに広げる。強みタグや長い表示名は折り返し、マスコットを本文に重ねない（[レスポンシブ方針](../architecture.md#レイアウトレスポンシブ方針)参照）。

## データの取得元

`GET /api/home/summary`は、ログイン中のユーザー本人のデータを次の取得元から返す（取得実装は`backend/src/caliboo_api/data/home_data.py`の`fetch_home_summary()`）。

- 表示名（`user.name`、および挨拶メッセージ`hero.message`の組み立て）: `users.display_name`
- 連続学習日数（`user.streakDays`）: ログイン中のユーザーの`home_profile`行
- 強みタグ（`strengths`）: `strength_candidates`の本人の承認済み候補
- 資格名・達成率（`certification`）: `home_profile.certification_id`が指す`certifications`行
- ショートカット（`shortcuts`）: ユーザーに依存しない固定値

## 強みの反映

強みは`strength_candidates`の本人の承認済み候補を動的表示する。候補がなければ空状態を表示し、`/strengths`で引用根拠と育成アクションを確認できる。旧`home_profile.strength*`は互換性のため残すが表示には使わない。
