# パステルUI改善仕様

## 目的と範囲

2026-09-28のGUI改善依頼に対応する。ユーザーの「まず仕様検討してから実装」「人間の承認は不要」という指示に基づき、以下を実装前の設計とする。

iOSのように情報の優先順位と操作先が分かる画面に整える。Calibooのミント・ピンク・ラベンダー・水色のパステルカラー、丸み、マスコットは継承する。認証、日報、課題、強み解析、資格勉強、OJTの業務ルールとAPIは維持する。

## 技術選定

React + TypeScript + MUIを継続し、CSS変数とMUIテーマの共通設定で見た目を統一する。新しいUIライブラリは追加しない。

!NOTE: iOSらしい情報階層・余白・角丸・半透明のナビゲーションはMUIのテーマと既存のコンポーネントで実現できる。別ライブラリへの置換はDialog/Drawerのフォーカス管理や既存フォームの再検証を増やすため、今回の目的に対する利点が小さい。Appleの外観を完全に再現することより、Webとしてのリンク・キーボード操作・レスポンシブ表示を優先する。

参照: [MUIのテーマ拡張](https://mui.com/material-ui/customization/theme-components/)、[Appleのナビゲーション設計](https://developer.apple.com/design/human-interface-guidelines/navigation-and-search)。

## 共通デザイン

- 背景は淡いニュートラル色、情報のまとまりは白いパネルに置く。濃い影を減らし、細い境界線と余白で区別する。
- パステルはカード背景・アイコン・補助装飾に使う。本文と補助文は濃くし、淡いボタン上には読める濃色を使う。
- 大きな見出し、本文、補助文の階層を統一する。ブランドの丸みを残しつつ、入力文字はスマートフォンで16px以上にする。
- 共通ボタン・アイコンボタンの操作領域は原則44px以上。キーボードフォーカスを明示し、無効状態・押下状態を見分けられるようにする。
- ダークモードにも同じ階層を適用する。動きを減らすOS設定では装飾アニメーション・移動を抑える。
- コンテンツ幅は最大1440pxとし、スマートフォンは16pxを基準に余白を調整する。全画面に共通テーマを適用し、主要画面の固定余白や折り返しを確認する。

## ナビゲーション

- 1200px以上では、既存の6画面と管理者用画面へのリンクを上部に表示する。現在地は背景色・文字・`aria-current`で表す。
- 1200px未満では既存のメニューボタンからDrawerを開ける。リンクにはアイコンと文字を併記し、明示的な閉じるボタンを設ける。遷移・Esc・背景クリックで閉じられる。
- 600px未満では下部に「ホーム」「日報」「課題」「資格勉強」「その他」の5項目を表示する。「その他」は同じDrawerを開き、「強み」「OJT」や管理者用画面へ移れる。
- 強み・OJT・管理者画面では下部の「その他」を選択色にする。資格勉強のチャットや課題詳細でも親のナビ項目を選択色にする。
- 下部ナビの高さと端末のセーフエリア分を本文下端に確保し、最後の操作を隠さない。上部にはテーマ切替・本人のストリーク・ログアウトを残し、320px幅でも操作可能にする。
- Drawerを開いたまま1200px以上へ広げた場合は閉じる。キーボード利用者は「本文へ移動」リンクでナビを飛ばせる。

!NOTE: 下部ナビに全機能を詰め込むと文字とタップ領域が小さくなるため5項目に絞り、全機能への既存リンクはDrawerに保持する。上部の1200px境界は作業開始時の実装に合わせ、管理者向けのリンク増加でも衝突しにくくする。

## ホーム

- ページ見出しと短い案内の下に、今日の振り返りと資格の進捗を配置する。
- 振り返りカードはAPIの挨拶とマスコットを使い、「日報を書く」を主操作として目立たせる。
- 資格の進捗はAPIの資格名と達成率をそのまま表示し、学習画面への導線を設ける。達成率に関係なく「あと少し」と断定する文言を避ける。
- ショートカットはAPIのラベル・説明・遷移先を使う。900px未満では縦に並べる。
- 強みは独立したパネルにまとめ、承認済みのタグと「根拠と成長のヒントを見る」を表示する。空の状態では日報や課題が材料になることを案内する。
- 読み込み中は骨格表示と状態テキスト、失敗時はエラー通知を表示する。

## 入力・その他の画面

- ログインを含む共通の入力・ボタン・ダイアログ・タグ・カードの配色、余白、角丸を統一する。
- 日報のKPT、課題・強みの一覧、資格勉強、OJTの機能と状態を保ったまま、狭い画面での余白・折り返し・読みやすさを調整する。
- チャットのIME送信制御、認証、下書き保存、課題提出などの操作ロジックは既存の検証対象として回帰確認する。

## 同時編集への対応

編集開始時の対象ファイルを記録し、編集直前に照合する。他セッションの変更があれば最新内容を読み直し、小さい差分で統合する。業務ロジックの全面置換や既存変更の巻き戻しを行わない。競合箇所がすぐ統合できなければ共通テーマから先に適用し、変更可能になった箇所から残りを反映する。

## 実装順序と完了条件

1. 本仕様と総合テスト観点を記録する。
2. デザイントークン、MUIテーマ、共通UIを更新する。
3. ナビゲーションとホームを更新し、主要画面へ適用する。
4. ナビの遷移・開閉・現在地・ロール・テーマ操作をテストし、既存テストと95%以上のカバレッジを確認する。
5. TypeScript検査と本番ビルドを実行する。
6. ブラウザで320/390/768/1024/1440pxの主要レイアウト、ライト/ダーク、フォーカス、横はみ出しを確認する。APIをモックした確認と実バックエンド確認は区別して記録する。
7. 画面仕様、アーキテクチャ、手動確認記録を実装に合わせて更新する。未確認事項がある場合は明記する。

## 実施結果（2026-09-28）

共通テーマ、ナビ、ホーム、入力・チャット・主要画面の表示へ適用済み。他セッションのクイズ送信制御・ログイン試行制限・追加テストを保持し、重複したカバレッジ設定を統合した。依存パッケージの追加・変更はない。

- `npm run lint`: 成功。
- `npm run test:coverage`: 32ファイル・243テスト成功。Statements/Lines 100%、Branches 97.99%、Functions 99.07%。TopNavは全指標100%。
- Vite本番ビルド: 成功。アクセス方針に従い`envDir: false`・`publicDir: false`で実行し、成果物は一時ディレクトリへ出力。JSチャンク約596KB（gzip約179KB）のサイズ警告は残る。
- Chromiumで101通りの表示確認: 横はみ出し・実行時例外なし。テーマ保持、ナビ・Drawer・ダイアログ・本文へのスキップ操作、下部ナビと本文末尾の重なりも確認。
- axe-core: ホームは両モードで検出違反なし。日報・学習チャット・OJTも両モードで検出違反なし。資格勉強は未選択ボタンの無効化と文字色を補正し、選択中・解答後の両モードで検出違反なし。

ブラウザ確認のAPIは表示確認用のモックであり、実DBとの結合確認を意味しない。iOS実機のSafari・VoiceOver・ソフトウェアキーボードは未確認。確認手順と範囲は [手動確認記録](manual-test-cases.md#パステルui改善の確認2026-09-28) に残す。
