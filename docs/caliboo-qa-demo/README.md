## 実機での再現（開発環境がある場合）

通常のCalibooリポジトリの開発依存（Python 3.12以降、Node/npm、PythonのFastAPI/SQLAlchemy/uvicorn、フロントエンドのnpm依存）が利用できること。GitHubのドキュメントブランチから本ディレクトリを取得し、実行時は検証済みの main に近いコードを使う。ソース全体を公開サーバーへ起動する操作ではない。

以下は macOS / Linux / WSL の例。リポジトリルートで、既存のPython仮想環境を有効化する。ローカルWindowsでは作業パスを置き換える。

```bash
SCRIPT="$PWD/docs/caliboo-qa-demo/replay_demo.py"
STATE="$HOME/caliboo-qa-demo-1126"  # 今回のための未作成ディレクトリ
python "$SCRIPT" prepare --repo "$PWD" --state "$STATE"
python "$SCRIPT" serve --state "$STATE"
```

- `prepare` は新規の隔離DB・専用講師/新入社員アカウントを作る。ランダムなログイン情報は実行ターミナルのみに出力する。既存の通常DBや実利用者には触れない。
- アプリを `http://127.0.0.1:5173/` で開く（ローカルPC内限定）。ポート8000・5173が使用中なら既存の開発サーバーを停止してから起動する。
- 別ターミナル、同じPython環境・SCRIPT/STATE変数のもとで次を実行する。

```bash
python "$SCRIPT" seed --state "$STATE"
```

前日1件だけをAPIで投入する。ブラウザーで新入社員として当日分（`02-report-browser.json` の request）を入力・提出する。日付は実演当日に合わせる。事前に2件とも投入しておきたい場合は `seed --both` を利用してよい（この場合、当日分をUIで入力する操作は省略）。

```bash
python "$SCRIPT" replay --state "$STATE"
```

このコマンドは**収録した実AI応答の再取込**を行う。AIの再推論はしない。日付以外の材料が一致しない場合は停止する。講師でログインし、強み → 対象者 → 新入社員（デモ） → 根拠を見る → 承認して表示。新入社員に切り替え、強み・ホームを表示する。別々のブラウザープロファイルが望ましい。同一ブラウザーならログアウトして切り替える。

```bash
python "$SCRIPT" verify --state "$STATE"
```

前後の本人・講師候補を表示する。終了はサーバー端末の Ctrl+C。作成した隔離ディレクトリ内にだけDB・ランダムなローカルの認証情報が残るため、必要がなくなったらサーバー停止後にその専用ディレクトリを削除する。共有やコミットはしない。

## 質疑応答での注意

- **精度は？** : 今回は機構の動作確認。20件／人間2名等の検証計画と、このデモの架空2件は区別する。
- **AIが勝手に評価する？** : 候補は講師確認の前には本人に表示されない。人事査定ではなく育成支援用。
- **何をAIに渡す？** : 実デモの独立Codex解析入力は材料スキーマと架空の日報。通常運用への展開では対象データ、保存、持出し、原文引用のアクセス管理などを情シスと確認する必要がある。
- **公開版でも動く？** : 掲載する体験版が静的再現の場合、日報送信・生の推論・永続化を行わない。ここで検証した本体の実機操作・手動取込とは区別する。
- **誤った形式のAI出力は？** : 初回応答の `notes` が配列だったためアプリは422で拒否。エージェントが型のみ修正して再取込し、元の材料・候補は変更せず成功した。この事実を原本と再出力で確認できる。
