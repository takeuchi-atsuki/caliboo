# 部署ナレッジに基づくOJT回答

GitHub #4。ユーザー承認済みのPL-6に対応する。部署資料の実在を確かめずに「手順がまとまっている」と返すテンプレートを、根拠を表示する回答へ変更する。

## 仕様

- 選択部署の登録ナレッジだけを検索する。日本語の連続2文字と英数字語を使い、現在の質問を優先する。追質問では同じ本人・部署の直近の質問も補助に使う。タイトルを本文より重く評価し、上位5件を対象にする。外部URLの取得や他部署への検索拡張はしない。
- openai設定時は、質問、部署名・補足案内、本人の同部署の直近12発言、検索結果から回答を生成する。入力に含まれる操作命令は資料として扱い、ツールを与えない。登録ナレッジの記載範囲で答え、根拠不足は講師への相談を案内する。
- 回答の根拠IDと引用が検索結果の原文に存在することを検証し、参照名と引用はサーバーで復元して表示する。空の根拠で断定する回答、他部署のID、原文と違う引用は保存しない。
- 検索結果なし・モデルによる根拠不足の判断は、固定の根拠不足案内を返す。モデルの自由回答で補わない。manual設定では関連資料の原文抜粋を返す。未設定時に外部通信はしない。
- 推論中にDBの書込みトランザクションを保持しない。成功した質問と回答を同じトランザクションで保存する。通信障害・不正出力は503、資料検索の障害でも回答を捏造せず失敗とする。フロントは入力と過去履歴を保持して再送を促す。
- 推論中に部署設定が変更された場合は409とし、最新の資料で再送する。画面を切り替えた後の応答は別部署へ混ぜない。既存の会話永続化・本人分離・明示的な講師相談と講師返信を維持する。

> [!NOTE]
> この検索は小規模な登録資料向けの語句照合であり、同義語や意味だけの一致は保証しない。引用検証も回答の意味的正確性までは証明しないため、原文を表示し、断定できない事項は講師への相談へつなぐ。

## 検証

部署と本人の境界、検索の順位・追質問・根拠不足、引用不一致、通信失敗後の再送、設定変更中の応答破棄、会話保存と講師相談をAPI・サービスのテストで確認する。フロントは参照名と引用の表示、送信失敗時の入力保持を確認する。外部APIの実通信は別途運用環境で記録する。
