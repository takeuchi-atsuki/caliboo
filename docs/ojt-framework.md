# 部署別OJTフレームワーク

## 適合性の判断

2026-09-28に既存仕様・実装を確認し、適切と判断した。Calibooの目的は新人の学習と講師の育成支援であり、OJTはすでに部署マスタ・部署別ナレッジ・利用者×部署の会話を持つ。相談の共通処理と部署の設定を分離することで、部署追加のたびに画面や会話処理を複製する必要がなくなる。

本仕様のフレームワークはCaliboo内の設定駆動の共通基盤を指す。独立SDKの配布、任意コードのプラグイン実行、研修全体のワークフローエンジンは別の要件として扱う。

## 初期実装の範囲

講師（既存の `admin` ロール）が管理画面から部署を追加し、部署ごとの表示名・アイコン・色・初期案内・質問候補・回答の補足案内・ナレッジを変更できる。再起動後も設定を保持し、既存のOJT両画面で利用する。

| 共通処理 | 部署ごとの設定 |
| --- | --- |
| 認証、相談の送受信、本人の履歴保存 | 部署名、アイコン、色 |
| 講師への明示相談、講師の返信 | 最初に表示する案内文、質問候補 |
| ナレッジ表示、入力検証、保存競合の検知 | ナレッジのタイトル・説明、回答に添える補足案内 |

既存の `admin` はすべての部署を設定でき、`member` は設定変更できない。各部署の担当講師に管理を委ねる運用は可能だが、担当部署以外の編集を禁止する権限制御は初期実装に含めない。所属部署によるOJT閲覧制限も追加せず、既存どおり全部署に相談できる。

> [!NOTE]
> 現在の権限は `admin/member` の2種類である。配属先を編集権限として流用すると、講師の担当部署と本人の所属部署を混同するため、部署別の管理権限が必要になった段階で担当関係を別途設計する。

## 設定と更新

- 部署IDは英小文字から始まる英小文字・数字・ハイフンの1〜40文字とし、作成後は変更しない。重複IDは409。
- 部署名は1〜100文字、初期案内は1〜4000文字、回答の補足案内は0〜4000文字。必須文字列は空白だけを拒否する。
- 質問候補は0〜8件、各1〜200文字。ナレッジは0〜100件、タイトル1〜200文字・説明1〜4000文字。配列の順序を表示順として保存する。
- アイコン・色は既存6部署の選択肢から選び、ダークモードでも既存の配色処理を利用する。
- 保存は部署情報・案内・質問候補・ナレッジを一括で確定する。取得時の `revision` が古い場合は409として全変更を拒否する。
- 部署の削除は提供しない。設定更新でも既存の会話、講師の返信、配属履歴を保持する。
- ナレッジ件数は登録済みの実件数を返す。既存のダミー件数を利用しない。

## 永続化と互換性

既存の `departments`・`department_messages`・`knowledge_items` を利用し、質問候補・補足案内・更新番号を保存する `ojt_configurations` テーブルを追加する。起動時は既存部署の不足設定だけを補完する。初期案内とナレッジは既存DBの内容を維持し、ユーザーが保存した設定をシードで上書きしない。DB削除は不要。

案内文は履歴とは別の現在の設定として表示する。変更後は新しい案内が表示され、過去の利用者発言・自動回答・講師返信は書き換えない。設定反映のタイミングは部署一覧の再取得・画面の再読み込みとする。

## 自動回答の扱い

既存のテンプレート回答を継続し、部署で指定した補足案内を回答に追加する。補足案内は平文で扱い、テンプレート式やコードとして実行しない。ナレッジの編集は参照一覧の編集であり、検索・学習・LLM連携を意味しない。画面にはテンプレート回答であることを表示する。

> [!NOTE]
> 部署の設定を増やしても自動的に回答精度は向上しない。「学習済み」などの表示は実態に合わせて登録ナレッジ数の表示へ修正する。将来の検索・LLM連携は回答生成層で拡張する。

## 管理画面

`/admin/ojt-settings` に部署一覧・新規追加・設定フォームを設け、講師用ナビゲーションから遷移する。一般利用者が直接アクセスした場合はホームへ戻す。保存失敗時は入力を保持する。競合時は最新の設定を読み直してから編集をやり直せる。読み込み中・保存中は操作を制限し、古い部署の応答が別部署のフォームへ混入しないようにする。

## 将来の拡張

育成ステップ・到達目標・評価項目、部署担当者の管理権限、設定テンプレートの複製・配布、公開前レビュー、ナレッジ検索・LLM連携を次段階の候補とする。これらは今回の相談機能の設定とは別のデータ・業務フローを必要とするため、利用部署の具体例をもとに追加設計する。

## 検証観点

2026-09-28にユーザー承認済み。[総合テスト観点](test-perspectives.md)に記録する。

1. 講師による部署追加・設定変更がOJT両画面へ反映され、部署間で設定が混ざらない。
2. 初期案内・質問候補・補足案内・ナレッジの順序と件数が保存どおりになり、0件も扱える。
3. 再起動で設定が保持され、既存DBの案内・ナレッジ・本人の履歴・講師返信・配属が失われない。
4. 未認証・一般利用者の管理APIアクセス、不正入力、未知の部署、重複IDを拒否する。
5. 古い更新番号での保存は全体を拒否し、保存失敗時の入力保持と再読み込みができる。
6. 管理画面への導線、部署切替時の応答競合、二重保存防止、両OJT画面とモバイル・ダークモードを確認する。

## 実装・検証結果

初期範囲を実装済み。講師用ナビゲーションの「OJT設定」から利用する。既存DBにはバックエンドの次回起動時に設定テーブルを追加する。

- backend: 統合後と同一のソースで単体514件・統合46件成功、全体カバレッジ99%。flake8警告ゼロ。
- frontend: 260件成功、行/文100%・分岐98.11%・関数99.23%。型検査・ビルド成功。
- ブラウザー: 一時DBと実APIで操作・表示22項目、長文境界3画面を確認。詳細は [操作確認の記録](manual-test-cases.md#部署別ojt設定2026-09-28) を参照。

全講師が全部署を編集できる。部署単位の編集権限、育成ステップ・評価項目、ナレッジ検索・LLM連携は初期実装の対象外。

PR準備時に最新mainを取り込み、ソース・テスト・設定233ファイルが上記検証済みの作業ツリーと一致することを確認した。OJT変更だけを移した独立作業ツリーでも、backend単体478件・統合43件とfrontend260件が成功している。
