# 個別学習と強みを育てるサイクル

2026-09-28の達成条件を、既存の講師承認フローを活かして実装する。

## 実装順序

1. 承認済みの強み・根拠・育成ヒントと配信課題を自動更新し、本人が行動を選択・編集・実践・振り返りできるようにする。
2. 日報、課題の進捗、回答、講師フィードバックを材料として、通常運転で生成AIが強み候補と個人別課題案を作る。キューは再起動で失わず、失敗時は再試行する。講師の承認後に本人へ表示する。
3. 既存イシュー #4〜#7 の学習チャット・OJT根拠・復習出題を改善する。
4. #3 の実日報評価を追跡し、実データと独立した人間ラベルがない限り妥当性を合格扱いしない。

## 本人の行動と自動更新

- 強み画面に「自分で決める次の一歩」を設ける。本人が自由入力、または承認済みの強みの育成ヒントを下書きにして、行動・達成の目安・期限を決めて保存する。
- 行動は本人だけが作成・更新できる。講師は対象者の行動と振り返りを閲覧できる。他の新入社員の行動は取得・更新できない。
- 状態は planned（予定）、in_progress（取り組み中）、completed（完了）、cancelled（見送り）。完了には振り返りを必須とする。編集時は版番号を照合し、古い編集は409で拒否する。
- 強みとの関連は任意。保存時に本人の承認済み候補を検証し、関連する強みの表現と育成ヒントをスナップショット保存する。その後の解析で強みが更新されても、本人が選んだ行動を自動変更しない。
- 強み画面とホームは表示中に5秒間隔で取得する。非表示中は定期取得を止め、画面に戻った時に取得する。古い対象者の応答は破棄する。通信エラー時には前回の表示と入力を維持し、更新失敗を表示する。
- 強み画面には本人に配信された課題と状態も表示し、詳細画面へ進める。講師には選択した対象者の課題が表示される。
- リアルタイムの目安は「サーバーへの保存・講師承認後、表示中の画面へ5秒＋通信時間で反映」。AI処理中・講師確認待ちの時間は別であり、未承認の推測を確定した強みとして表示しない。

> [!NOTE]
> 行動を自動で割り当てると主体性を損なうため、AIの育成ヒントは入力候補に留める。本人の保存操作で初めて行動として記録する。完了時の振り返りは達成を自己評価する記録であり、自動的な強み確定の証拠にはしない。

## 検証観点（2026-09-29ユーザー承認済み）

- PL-1: 本人の行動作成・編集・開始・完了と振り返りが永続化される。未承認・他人の強みを関連付けできず、古い版の編集と振り返りなしの完了を拒否する。
- PL-2: 講師は対象者の行動を閲覧でき、本人以外の更新と他の新入社員の閲覧を拒否する。
- PL-3: 承認と課題配信が表示中の画面へ自動反映される。対象者切替・非表示・アンマウント・通信失敗・編集中の更新で漏えい、二重通信、入力消失を起こさない。
- PL-4: 本人の日報・課題進捗・講師フィードバックから生成AIの解析と課題案作成が起動し、引用検証と講師承認を経て本人だけに届く。
- PL-5: provider未設定・タイムアウト・不正JSON・根拠不一致・再起動・重複処理・古い結果を扱い、未検証出力を保存・配信しない。認証情報はDB・画面・ログに出さない。
- PL-6: OJTは部署内の根拠、学習チャットは対象問題と会話文脈を使う。根拠不足・障害から再試行でき、採点前に正解情報を渡さない。
- PL-7: 復習は本人の誤答・期限を優先し、分野・連続同問抑制・問題数が少ない場合・正解済み重複集計・既存進捗を維持する。

`test-perspectives.md` に承認と実際のテストへの対応を記録する。
