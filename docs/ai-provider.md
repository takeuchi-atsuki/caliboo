# 生成AI providerの設定と検証

2026-09-29時点では、初回の個人別課題案に適用する。強み解析と課題案再生成の自動ワーカーは GitHub #11 で継続実装する。

## 設定

既定は`CALIBOO_AI_PROVIDER=manual`。初回課題案は従来のルールベース、強み・再生成はCodexセッションの取込を維持し、外部APIを呼ばない。

| 環境変数 | 値・既定 | 用途 |
| --- | --- | --- |
| `CALIBOO_AI_PROVIDER` | `manual`（既定） / `openai` | 初回課題案の生成器 |
| `CALIBOO_AI_MODEL` | openai時に必須 | 利用可能なStructured Outputs対応モデルを運用側で指定 |
| `OPENAI_API_KEY` | openai時に必須 | サーバーの実行環境から取得する秘密値 |
| `CALIBOO_AI_TIMEOUT_SECONDS` | 30（1〜120の有限数） | 外部通信のタイムアウト秒数 |

起動環境のシークレット管理を使い、キーをソース、設定画面、DB、コマンド引数、共有ログに保存しない。設定ファイルをアプリが自動で読み込むことはない。実際に課題案を生成すると課金を伴う外部通信が起きるため、利用するモデル・権限・支出上限は運用側で設定する。

## 入出力と失敗時の動作

- OpenAI Responses APIの`text.format`でJSON Schemaを指定する。`store=false`、ツールなし。仕様は[公式Structured Outputsガイド](https://developers.openai.com/api/docs/guides/structured-outputs)を参照。
- 対象者の直近5件の提出日報・直近20件の講師フィードバック・本人の課題進捗件数・利用可能テーマだけを送信する。表示名、ログイン情報、他人の材料を入力に含めない。本文内に本人が記載した名前などは原文の一部として残る。
- 入力本文は命令として扱わないと指示し、モデルにファイル・ネットワーク・ツール操作を与えない。本文の意味まで機械的に正しいと保証するものではなく、講師の確認・編集・配信を必須とする。
- 送信材料はUTF-8で200KB以下、応答は1MB以下。上限超過では本文を切り詰めず失敗にする。出力の型、5〜480分の目安、テーマの許可、1〜10件の材料IDと原文引用を検証する。出典種別・日付・欄名は入力から復元し、モデルが作った出典を採用しない。
- モデルが拒否・未完了・不正JSON・根拠不一致を返した場合、課題案を保存しない。講師の生成APIは503で再試行を案内する。再試行は講師の操作で行い、同一HTTP処理内では繰り返さない。LLM障害をルールベースの生成成功へ置き換えない。
- 日報提出時の自動生成に失敗しても提出済み日報を保持する。同日の生成枠を解放し、次の日報提出時に再試行可能にする。自動処理の失敗状態の可視化・非同期化は#11で対応する。
- 生成が重なっても、確認待ちの判定とINSERTを同じSQL文にすることで、対象者の確認待ちを重複作成しない。既存の確認待ちは再生成せず返す。
- 配信済み・見送り済みテーマは除外する（既存の汎用ふりかえりテーマは再利用可）。初回案の`generator`にはprovider・設定モデル・プロンプト版を記録する。

> [!NOTE]
> 引用が入力中に存在することと、教育効果があることは別の検証事項である。LLMの出力を見た人間ラベルや合成データで、実日報評価（#3）の合格を代用しない。実provider接続と教育的妥当性は、このネットワーク遮断下の契約テストとは別に評価する。

## 検証の対応

ユーザー承認済みのPL-4/5に対応する。`test_llm.py`でHTTP入出力・秘密値・上限・拒否・障害、`test_llm_proposals.py`（単体）で材料選択・引用・テーマ・同時作成、同名の統合テストで確認待ち・配信・所有者分離・失敗後の再試行を検証する。実ネットワーク接続は行わない。
