# 限定試用向け暫定Web公開（#43）

## 目的と利用範囲

RC3統合検証後の画面とAPIを同じオリジンのHTTPSで提供し、所有者が許可した試用者だけが別端末から操作できるようにする。実運用・人事評価・研修記録の永続保存は目的としない。

- 日報、OJT、資格勉強、課題演習、強み・育成支援、講師の管理機能は既存のアプリを使用する。外部AI接続は行わず、manualモードの動作のみを確認する。
- 新規のプロセス専用一時SQLiteに、架空の講師と新人の2アカウントを作る。既存のユーザー・DB・実日報は持ち込まない。開発用ダミーアカウントの自動投入も行わない。
- 再起動、再デプロイ、サービスの休止・停止でDB内の入力、追加アカウント、パスワード変更等が失われ、試用開始時の状態へ戻る。同一プロセス内では通常の保存・再ログインができる。
- 実データ、個人情報、業務資料、資格情報は入力・添付・インポートしない。ブラウザのローカル保存領域（課題ワークスペース等）も合成データ専用とし、終了時にサイトデータを消去する。
- 試用ビルドではログイン画面と認証済み画面に注意表示を出す。フォントとアイコンのCSS・フォントファイルはnpmで管理した依存から自サイト配信し、独立したPoCモデル閲覧ページは配信しない。ライセンスはビルドの`assets/font-licenses.txt`に含む。

> [!NOTE]
> `python -m caliboo_api.trial` は通常のローカル開発サーバーとは別の公開専用入口。必須設定が欠けていれば起動せず、Viteの開発サーバーや通常の`caliboo_api.main:app`を公開して代用しない。

> [!NOTE]
> issue #43 の単独PRは公開構成の差分のみを含む。RC3の先行改修を混在させず、公開用にはRC3と#43を統合検証したコミットから、その時点のソース許可リストを用いて生成する。

## 提供ソースの作成（完全チェックアウトのみ）

リポジトリのルートで、検証予定のコミットを指定する。以下では`HEAD`を例にする。

```bash
python3 devel/package_trial.py --root . --ref HEAD --output ../caliboo-trial-delivery
```

新しい空の出力先に`source/`（ディレクトリ）と`caliboo-trial-source.zip`（同じ内容のZIP）が作られ、出力にはコミットID・ファイル数・ZIP SHA-256が表示される。

`devel/trial-source-allowlist.txt`に列挙したコミット済みの通常ファイルだけを取り出す。履歴、既存DB、実日報・PoC実行のトレース、ログ、テスト、秘密設定、ローカル依存、ビルド生成物、開発AI設定は含めない。出力物の許可リストとZIPの内容が一致することを確認する。新規のソースを追加する場合は内容を確認して許可リストも更新する。既存の通常配布ZIPはこれとは別用途。

開発で利用する架空のシード台本・ダミー定義は業務機能の実装ソースに含まれるが、限定試用では開発用ユーザーのパスワードを使用せず、実行時に所有者が設定する試用専用の資格情報だけを初期登録する。

> [!NOTE]
> Render等に渡すのは、選別後の`source/`の内容だけ（ZIPを使う場合は展開後の内容だけ）。RenderがGitリポジトリやコンテナイメージを要求する場合も、選別済みソースから作成した提供専用の非公開リポジトリ・イメージを使う。本体リポジトリの履歴やPoC記録のあるブランチを直接接続しない。外部送信に必要な権限と費用を確認するまで、ここでは提供物の生成にとどめる。配布物は試用専用であり、通常開発向けの文書・ツール・ページを網羅しない。

## 所有者が起動時に設定する環境変数

下表の山括弧付き値は説明用のプレースホルダ。実際の値をソース、ZIP、Git、ビルド引数、コマンド履歴、公開ログに記録しない。試用用シークレットは所有者が決め、試用者にだけ別経路で知らせる。

| 環境変数 | 値・条件 |
| --- | --- |
| `CALIBOO_AI_PROVIDER` | `manual` 必須 |
| `CALIBOO_DEMO_SEED` | `false` 必須 |
| `CALIBOO_COOKIE_SECURE` | `true` 必須 |
| `CALIBOO_TRIAL_ORIGIN` | `https://<試用ホスト>`（末尾スラッシュ・パス・明示の443なし。試用時の正確なHTTPSオリジン） |
| `CALIBOO_TRIAL_ACCESS_PASSWORD` | `<試用アクセス用パスワード>`：24～128文字の空白でない表示可能ASCII。入口のBasic認証ユーザー名は`trial`固定 |
| `CALIBOO_TRIAL_INSTRUCTOR_PASSWORD` | `<試用講師パスワード>`：16～128文字の表示可能文字、講師のログインIDは`trial-instructor` |
| `CALIBOO_TRIAL_MEMBER_PASSWORD` | `<試用新人パスワード>`：16～128文字の表示可能文字、新人のログインIDは`trial-member` |
| `PORT` | ホスティング側が指定するHTTP待受ポート（既定`10000`） |
| `CALIBOO_TRIAL_PROXY_IPS` | `<確認済みTLS終端プロキシのIP/CIDRのカンマ区切り>`：プロキシモードで必須。全ネットワークを信頼しない |
| `CALIBOO_TRIAL_TLS_CERTFILE` / `CALIBOO_TRIAL_TLS_KEYFILE` | `<ローカルTLS証明書のパス>` / `<ローカル秘密鍵のパス>`：直接TLSモード（ローカル確認）で両方必須。プロキシモードでは設定しない |

3種類のパスワードには互いに異なる十分に長い試用専用の値を設定する。`CALIBOO_DATABASE_URL`、`CALIBOO_SQLITE_PATH`、`OPENAI_API_KEY`、`CALIBOO_AI_MODEL`はすべて未設定でなければならない（空文字で定義することも不可）。既存DB接続先などを含む環境変数グループを読み込まない。

入口Basic認証と既存のアプリ内認証・ロール判定は別々に維持する。ブラウザが最初の入口認証を保持することがあるため、アプリでログアウトした後にブラウザのプライベートウィンドウも閉じること。認証情報をURLに含めない。

## ローカルで正式ビルドと試用入口を確認

Python 3.12以降、Node.js 22とnpm、信頼可能な開発用TLS証明書・秘密鍵（ローカルホスト向け、ソース外に置く）が必要。完全チェックアウトまたは提供ソースのルートで次を実行する。試用専用のシェル・仮想環境を使う。

```bash
python3 -m venv ../caliboo-trial-venv
source ../caliboo-trial-venv/bin/activate
python -m pip install -e ./backend
(cd frontend && npm ci --include=dev && npm run build -- --mode trial)
```

上表に従って起動環境を設定する。ローカルでは`CALIBOO_TRIAL_ORIGIN=https://localhost:10000`、`PORT=10000`を例とし、証明書と鍵のパスを指定して直接TLSモードを選ぶ。認証用3変数は非表示の対話入力などで設定し、秘密値をファイルへ書き出さない。

```bash
python -m caliboo_api.trial
```

直接TLSモードはループバックのみで待ち受ける。ブラウザから`https://localhost:10000/`を開き、正常なTLS証明書検証を確認する。試用時と同じ正式ビルド・入口を用いる。停止は`Ctrl+C`。停止後に同じ起動手順を実行すれば新規の試用環境で始まる。

## Renderの無料枠で公開する場合（外部公開の実施条件）

公開の実施前に、[Freeの条件](https://render.com/docs/free)と[Billing画面の使用量](https://render.com/docs/render-dashboard#manage-billing)を所有者の対象ワークスペースで再確認する。2026年11月時点の公式説明では、無料Webサービスは次の制約がある。

- 同一ワークスペースに月750インスタンス時間。15分間リクエストがなければ休止し、次のアクセスでは起動待ちがある。ローカルファイルは休止・再デプロイ・再起動で失う可能性がある。
- 送信帯域とビルドパイプライン時間も含まれる月間枠を消費する。支払方法を登録済みの場合、枠超過が追加請求になる場合がある。支払方法未登録の場合は枠超過に応じて無料サービスや新規ビルドが停止する。

このため今回の無料試用は、無料ワークスペース、無料Web Service 1インスタンス、支払手段未登録、十分な無料残枠、追加DB・永続ディスク・有料ドメイン・有料オプションなしを実際の画面で確認できる場合に限る。登録や構成変更が課金・クレジットカード登録を必要とする場合、または費用ゼロを確認できない場合は、所有者の承認を得るまでサービスを作成しない。休止防止の定期アクセスや自動アップグレードを設定しない。

[Render Web Services](https://render.com/docs/web-services)ではエッジでTLSを終端し、サービスへHTTPを転送する。アプリ側には直接接続するTLS終端プロキシのIP/CIDRを確認して`CALIBOO_TRIAL_PROXY_IPS`を設定する必要がある。公開資料から対象インスタンスの具体的な信頼範囲までは確定できていない。プラットフォームで送信元・HTTPS転送の信頼条件を確認できない場合は公開を見合わせる。受信を全ネットワーク信頼に緩和しない（[RenderのFastAPIプロキシ推奨事項](https://render.com/articles/fastapi-production-best-practices)）。

条件を満たした場合だけ、選別済みの提供ソースを使用して[Web Service](https://render.com/docs/web-services)の設定を次のように指定する。アカウント登録、Git連携、外部アップロードやサービス作成はこの手順書作成時点では未実施。

| 設定 | 値 |
| --- | --- |
| Service type / Runtime | Web Service / Docker |
| Instance | Free、1インスタンス |
| Dockerfile path / Build context | `./Dockerfile.trial` / `.`（選別済み提供ソースのルート） |
| Docker Command | 未指定（Dockerfileの`python -m caliboo_api.trial`を使用） |
| Health Check Path | `/healthz` |
| Auto-Deploy | Off（自動デプロイなし） |
| Environment | 上表のtrial必須設定を実行時に設定。公開URLに合うHTTPSオリジンと確認済みのプロキシIP/CIDRを使用 |
| Datastore / persistent disk | 作らない（プロセス専用一時SQLiteのみ） |

DockerfileはNodeのビルドステージでロックファイルを使って画面を正式ビルドし、PythonステージへAPIソースと完成した画面だけを配置する。コンテナは非rootユーザーで起動する。アプリはプロキシ利用時に`0.0.0.0:$PORT`で1ワーカー起動し、匿名の`GET /healthz`は準備状態を示す`{"status":"ok"}`のみを返す。アプリと静的ファイルの提供元は同じURLであり、APIドキュメントを外部公開しない。

## 受け入れ確認（合成データのみ）

1. 正式ビルドの試用URLがHTTPSで開くこと。入口で`trial`の認証が必要で、認証後はログイン画面と「限定試用環境（合成データ専用）」の注意表示が出ること。`/healthz`は匿名でも状態のみを返す。
2. 所有者が用意した新人のログインでホーム、日報、OJT、資格勉強、課題演習、強みを閲覧し、架空のKPTを提出する。講師専用の操作が新人の通常画面に出ないことを確認する。
3. ログアウトし、同一サービス内で新人として再ログインし、提出した合成日報が残っていることを確認する。
4. 講師としてログインしユーザー管理や日報・課題関連の通常操作を確認する。実データや外部AIを使わない。講師としてログアウトする。
5. 再起動する。最初に設定した試用アカウントでログインでき、先ほどの合成日報は新しいプロセスで引き継がれないことを確認する。ブラウザのローカル保存は終了時に消去する。
6. 公開時は追加で別端末から同じHTTPS URL・資格情報で確認し、Renderの実行状態・無料残枠を確認してから試用者に案内する。公開サービスの接続、実TLS終端、費用状態はローカル確認だけでは代替できない。

## 試用終了時の停止・撤去

試用期限を設け、無料枠の条件が変化したり、不要になった時点でサービスを停止する。所有者がRender Dashboardで対象Web Serviceを確認し、自動デプロイを停止したままSuspendしてURLが利用できないことを確認する。完全撤去の判断後に対象サービスをDeleteし、不要な提供専用のGit接続等を解除する（本体リポジトリや他サービスは消さない）。試用資格情報の共有を終了し、ブラウザのサイトデータを消去する。Billing画面で対象の利用状況を確認する。

本手順は本番公開の構成ではない。永続保存・個人情報処理・外部AI・課金の必要な環境へ変更する場合は別途合意が必要となる。
