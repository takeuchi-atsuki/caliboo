# 問題と会話を引き継ぐ学習チャット

GitHub #5、承認済みPL-6に対応。引き継いだ問題に固定の挨拶を返していた処理を、実際のAPI応答へ置き換える。

- 学習チャットは質問、直近12発言、任意の問題文と選択肢を受ける。役割はme/botのみ。履歴は表示中のタブの会話から組み立て、初期挨拶・失敗した送信は生成用の履歴へ含めない。
- 問題の引継ぎは公開済みの問題文・選択肢・画像代替文だけ。採点用の正解番号・解説をstateやAPIやモデル入力へ含めず、サーバーも問題DBの解答を参照しない。画像ファイルやURLはモデルに送らない。
- openai設定時は共通生成基盤を利用し、質問・問題・直近会話に沿って、用語、判断手順、確認の問いを日本語で示す。入力文の操作命令は実行しない。問題情報が足りないときは不足を確認し、採点結果を断定しない。モデルが問題文から行う推論と正解DBによる採点は区別する。
- manual時は、問題と質問を使った考え方の整理を返す。事実の説明を生成したかのような固定応答にはしない。
- 問題引継ぎ直後にAPIへ1回だけ送信し、StrictMode・location.state消去でも重複しない。引継ぎの文脈はその画面の会話中保持し、再読み込み後は従来どおり引き継ぎを繰り返さない。
- 送信中は二重要求を防ぐ。失敗時は前の会話と入力を保持し、再送を案内する。失敗した質問を履歴に重複追加しない。画面を離れた後の応答は破棄する。関連過去問の取得失敗は会話を妨げない。
- 入力の形・長さ・履歴数を制限し、設定・通信・不正出力は503、入力不正は422。認証情報や原文をエラーへ出さない。

!NOTE: 学習チャットの履歴は従来どおりタブ内に保持する。新たな履歴DBや他人の会話参照は追加しない。正解データの非送信は機械的に検証し、モデル回答の教育的正確さは運用評価で確認する。

## 検証

APIの問題/会話文脈と上限、正解データ非送信、型違反・障害、ネットワーク遮断下のHTTP契約を確認する。フロントでは問題引継ぎの自動送信、StrictMode・画面離脱・二重送信、失敗からの再送、最新会話と問題の保持を検証する。


## 上限と公開問題の保持

質問・各履歴の本文は1〜10000文字、問題文は1〜10000文字、選択肢は1〜10件・各1〜2500文字。生成用の入力が180KBを超えるときは古い履歴を丸ごと外す。現在の質問・問題を切り詰めて別の意味にせず、共通の200KB制限も適用する。初回のAPI質問は短い「この問題の考え方を教えてください。」とし、問題本文・選択肢は専用のquestion欄に1回だけ入れる。
