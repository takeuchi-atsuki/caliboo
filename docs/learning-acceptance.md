# 個別学習サイクルの達成状況

2026-09-29時点。要求された機能を実装し、合成データによる自動テストとブラウザーで確認した。実API接続と実日報による妥当性評価は未完了のため、運用上の最終達成とは区別する。

## 条件と証拠

| 達成条件 | 実装 | 検証と残る確認 |
| --- | --- | --- |
| 教育内容のパーソナライズ | 本人の材料から個人別課題案を生成し、講師が調整・配信。本人の誤答と期限によるクイズ復習 | 課題案の材料・引用・配信先、復習順序・非重複集計を自動検証。実モデル接続は #19 |
| 強みの創出と可視化 | 引用付き候補を講師が承認し、根拠・育成ヒントを本人に表示。本人が行動・達成条件・期限・振り返りを設定 | 承認前非公開、本人分離、行動の保存・完了・振り返りをAPIとブラウザーで確認。実日報の精度と教育効果は #3 |
| 日報・課題進捗・講師フィードバックの生成AI解析 | 三つの入力契機から永続ジョブを作成。外部provider、原文検証、再試行、古い結果の破棄、講師承認 | 外部HTTPを差し替えた契約テストと、実lifespanワーカーで確認。実通信は #19 |
| リアルタイム受信による主体的行動 | ホーム・強み・課題を5秒間隔で取得し、本人が次の一歩を決める。非表示時は停止し、入力を保持 | 承認後の自動反映と入力保持をブラウザーで確認。反映は保存・承認後5秒＋通信時間。推論と講師確認の時間は別 |

AIが提示する内容は行動の候補であり、本人の選択を置き換えない。引用検証の成功は教育効果の証明ではない。

## 運用確認に必要なもの

1. [#19 実API接続](https://github.com/takeuchi-atsuki/caliboo/issues/19): 検証用実行環境へモデルとAPIキーを設定し、[provider設定](ai-provider.md)と[ワーカー手順](ai-worker.md)に従う。現在のセッションではキー・モデルは未設定。設定ファイルや秘密値を共有する必要はない。
2. [#3 実日報評価](https://github.com/takeuchi-atsuki/caliboo/issues/3): 解析結果を見ていない実日報20件と、独立した人間評価者2名を用意し、[ホールドアウト手順](strength-holdout.md)で評価する。現在は実日報の一致率・受容率を測定していない。

合成fixture、Codex自身が作った人間ラベル、モデル出力を見た後のラベルを、実日報の合格実績として数えない。
